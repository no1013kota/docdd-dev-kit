## キット共通の約束（docdd）

### 前提：運営者は個人（非エンジニア想定）

**1人の非エンジニアが運用する。修正の量より運営のしやすさを優先し**、迷ったら次を満たす方を選ぶ。「動くが運営者には扱えない」形で完了扱いにしない。

1. **黙って壊れない** — 失敗は必ず記録し、運営者が気付ける経路（通知・状態確認コマンド）へ載せる。**正常な空と失敗による空を別の値で表す**（0件が「該当なし」か「取得失敗」かを呼び出し側が説明できる）。
2. **原因が開発知識なしで辿れる** — 画面かコマンド1つで、いま何が起きているかが分かる。ログを読ませない。
3. **手順を人間の記憶に依存させない** — 欠かせない手順（DB変更の適用など）は1コマンドへ畳むか、忘れたら止まる形にする。
4. **費用が見える** — 従量課金（AI・外部API）の実績と上限超過を運営者が把握できる。
5. **判断はまとめて求める** — 小さな確認を挟まず、決めることを整理して「要決定」へ集約する。

反する実装は、指摘して直す。回避策を文書に書いて済ませない（手動の回避策は忘れられる）。

### 最重要ルール：ドキュメントとコードの同期

`docs/` は常に実装と一致させる（正本は1か所）。運営者が先に書き換えた仕様は実装に合わせて戻さず、何も書かずに `/docdd:add-task` を打ってタスクにする。

1. 仕様に影響する変更（機能・挙動・DB・API・画面・プロンプト）は、**同じ作業単位の中で**該当文書も直す。文書の更新までが完了条件。
2. どの文書を直すかは `docs/README.md` の地図と所有ルールに従う。
3. 要件が変わるなら PRD と変更履歴を直す。実装の詳細は PRD ではなく `docs/requirements/` に書く。
4. コミット前に `/docdd:doc-sync` で同期漏れを見る（`/docdd:dev-loop`・`/docdd:refactor`・`/docdd:speed-up`・`/docdd:security-audit`・`/docdd:ui-polish` は中で呼ぶ）。**スキルを通さずコードを直したときは必ず自分で実行する。**
5. 文書に無い仕様判断を実装したら正本へ書き戻す。技術判断は `docs/decisions/` に ADR で残す。

### 開発の進め方

- スキルの呼び方: Claude Code は `/docdd:dev-loop`、Codex は `$docdd:dev-loop`（この文書では `/docdd:` と書く）。
- 流れ: 要望 → `/docdd:add-task`（仕様書を書き換えたあとは引数なしで、仕様書からまとめて起票）→ `/docdd:dev-loop`（中で doc-sync と検証を呼ぶ）→ 全部終わったら `/docdd:release`。連続自動開発は `/loop /docdd:dev-loop`。
- 必要なら `/docdd:release` の前に仕上げる: `/docdd:refactor`（振る舞いを変えず整える）・`/docdd:speed-up`（表示が遅い）・`/docdd:security-audit`（公開前や、ログイン・課金・外部連携を触ったあと）。
- **要望は `/docdd:add-task <要望>` で起票してから実装する。** `todo` が無ければ `/docdd:dev-loop` は起票のしかたを伝えて止まる。
- タスクは `tasks/BACKLOG.md`（状態と書式は同ファイルの「運用ルール」）。**終わったタスク（`done`・`dropped`）と決まった判断は `node scripts/backlog-archive.mjs` で `tasks/archive/BACKLOG-done.md` へ移す。** アーカイブは丸ごと読まず、ID や言葉で検索する。新しい T-・D-番号は、アーカイブも含めた最大の次。
- 1タスク = 1コミット。メッセージにタスクIDを含める（例: `feat(T-01): メール認証を実装`）。コミットの承知やブランチ運用の決まりは `AGENTS.md`「スキルへの追加指示」に書く（スキルは本文より追加指示を優先する）。
- 運営者の判断が要ることは勝手に決めず、`tasks/BACKLOG.md` の「要決定」へ（可能なら暫定案を添えて）書いて先へ進む。決まったら正本（事業判断は `docs/PRD.md`、画面・データの細部は `docs/requirements/`、技術判断は `docs/decisions/` の ADR）へ書き戻す。
- 仕様の正本: 何を作るか → `docs/PRD.md`、どう作るか → `docs/requirements/`、ほかに運営者が `docs/` に置いた仕様書（`docs/_imported/` の原文は除く）。版はファイル名でなく文書冒頭の表を正とする。
- 検証と反映は `AGENTS.md` の「検証コマンド」「反映コマンド」表のコマンドを使う。「無い」の行は飛ばし、`{{…}}` のままの行は未記入として実行しない。どちらも理由を報告する。

### 変更影響 → 必須の検証

境界をモックしたテストでは確かめられない所（外部サービス・ブラウザ・メールなど）があるため、**触った層で必須の検証をこの表で機械的に決める（判断で選ばない）。該当行はすべて実行し**、実行しなかった行は理由を報告する。このプロジェクトに無い層（課金・定時処理・外部 AI など）の行は「該当なし」と報告する。

**触った層は、未コミットの変更と直近のコミットの両方から特定する**（`git status --short`・`git diff HEAD` に加え、`git log --oneline -10` で今回の範囲を見て `git diff <その手前のコミット>..HEAD`。コミットが無ければ未コミット分だけ）。コミット後や、別の会話で「テストして」と頼まれたときも直近のコミットまで見る。範囲が決まらなければ推測せず運営者に聞く。

表の『』は `AGENTS.md`「検証コマンド」表の行を指す。

| 触った層 | 必須の検証 |
|---|---|
| DB のスキーマ・権限・migration | `/docdd:verify-integration`（ロール権限を含む） |
| サーバー側の処理（API・Server Action） | 本番実装を実 DB（『テスト用 DB』）で通すテスト |
| **DB へ書く値の形式**（キー・列挙・日付書式） | その値を**実際に insert する**テスト（文字列の組み立ての単体テストでは足りない） |
| **外部 AI／外部 API の呼び出し・プロンプト・出力の形** | 受理されるかの検査 ＋ **実物で1周** |
| **画面（Web）** | `/docdd:ui-polish` ＋ **実データを描画する E2E**（画像・表・レイアウト崩れはブラウザでしか出ない） |
| **画面・操作（Web 以外）**（ゲームのシーン・UI、ネイティブアプリの画面） | 『E2E（実際に動かす）』行の自動テスト（例: Unity の PlayMode テスト）。自動で確かめられない見た目・操作は、運営者に確かめてもらう手順（場面・操作・期待する見え方）を示し、「運営者確認待ち」と報告する |
| **エンジンやツールが保存するファイル**（ゲームエンジンのシーン・プレハブ・.meta、Xcode・Android Studio のプロジェクト設定など） | 手で書き換えず、エンジン・ツールの操作かその API を使うスクリプトで変える。対になるファイル（Unity の .meta など）の増減を `git status` で確かめて報告する |
| 外向き副作用（外部サービスへの送信・メール・課金・外部サービス上のデータの削除） | 非本番で実行されないこと（環境ガードの有無）の確認 |
| **古いものを消す処理**（保持期間つきの削除、どこからも使われていないものの掃除） | 消される側を**指しうる場所をすべて挙げ**、**「参照あり」と「参照なし」を1件ずつ置いて、参照ありだけが残る**ことを本物（『テスト用 DB』・実際に置いたファイル）で確かめる。判定が複数か所（1件ずつ見る側と一括で拾う側）にあれば、すべてで確かめる |
| **本番ビルドでしか出ない設定**（CSP・キャッシュ・事前描画） | 『ビルド』＋『本番モード起動』＋ 実ブラウザで公開ページのコンソールエラーまで見る |
| **外部サービス側の設定に依存する画面**（人間確認・OAuth・決済） | 実ブラウザ（相手側の許可ドメイン等はコードに現れない） |
| 定時処理 | `/docdd:verify-integration` ＋ 該当処理を実際に1回動かし、**結果の中身**まで確認 |
| **検査そのもの**（テスト・lint 規則・規約を機械で守るスクリプト）を足した・変えた | **わざと違反を入れて、その検査が落ちることを1度確かめて**から戻す（`docs/operations/development-and-testing.md` §3・§5）。走査して違反を探す検査なら、**検出のしかたごとに「1件以上当たること」**も検査に入れる |
| **ドキュメントのみ（docs・tasks・AGENTS.md）** | `/docdd:doc-sync` ＋『docs の検査』＋『未記入欄の検査』 |
| 上記以外 | 『全検査（push 前に1回）』 |

- **公開先へ反映したとき**は、公開先の画面を実際に開いて確認したことまで報告する（公開先の設定値は手元のテストでは確かめられない）。
- **migration（DB の構造変更）を含む反映**では、本番 DB を変える前に `/docdd:release` が「反映コマンド」表の『本番 DB のバックアップ』行でバックアップを取る。取れなければ反映しない。行が未記入なら、その場で候補を示して聞き、決めた内容を行へ書く。
- **公開した版に不具合が出たとき**に前の版へ戻す手順は「反映コマンド」表の『戻し方』行に書く。バックアップ（データを戻す）と『戻し方』（版を戻す）は別物で、版を戻しても DB はそのまま。控えに入らないもの（利用者が上げたファイル・外部サービス側の設定）は `docs/operations/backup-and-restore.md`。
- **「実物を1周」**は、リクエストが受理されることでは足りず、**応答をアプリが扱えて最終成果物が正しいところまで**見ること。『実物1周の費用上限』行の金額を上限にし、超えたら止めて報告する。**その行が未記入（または「無い」）なら、実物1周は実行せずに報告する。**
- いつ回すか（変更ごと・コミット前・push 前）と落とし穴は、`docs/operations/development-and-testing.md` の §2・§5。

### Definition of Done（全タスク共通）

### 規約

- 文書・コミットメッセージ・応答は日本語。プロジェクトの既存の文書・コミットが別の言語なら合わせる（決め方は `AGENTS.md`「スキルへの追加指示」に書いてよい）。コードの識別子・コード内コメントは英語。
- **`git add -A`（や `git add .`）を使わず、パスを明示して `git add` する**（並行して編集中のファイルを巻き込むため。プラグインの hook も止める）。
- 秘密情報（APIキー・トークン・暗号鍵）は `.env` だけに置く（`.gitignore` での除外は `/docdd:init` が確かめる）。変数名の一覧は値を書かずに `.env.example` へ。コード・文書・コミットに実キーを書かない。
- スクショ・trace・計測用の一時ファイルはコミットしない。置き場は `/tmp/claude/`（Web なら playwright-cli が作る `.playwright-cli/` も .gitignore 済み）。
- 外部 API の仕様は変わりやすい。実装時は公式ドキュメントで最新仕様を確かめる。
